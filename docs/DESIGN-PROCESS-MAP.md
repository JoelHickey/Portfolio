# Your design process — map for the FCTG talk

Single reference for **discover → define → develop → deliver** as it appears in your case studies and the deck.

---

## Four phases (slide: “The design process”)

| Phase | What it is in your work |
|-------|-------------------------|
| **Discover** | Problem framing, workshops (e.g. global workshops, problem discovery, voting on pain points), key findings, matrix/prioritisation, competitive analysis, risk assessment. Evidence and alignment before solution shape. |
| **Define** | Opportunity and direction. Ideation (e.g. design studio, Crazy 8s, 50+ reframes), concept exploration (e.g. six directions, one chosen), usability goals. Clear “what we’re building and why.” |
| **Develop** | Making it real. Wireframes → hi-fi prototypes, flowcharts and annotated prototypes for handoff, usability testing (task-based, think-aloud, A/B), design handoff to eng, build cycles, real-time collaboration. |
| **Deliver** | Ship and learn. UAT, pilots, training, change management, rollout, success tracking (adoption, task completion, time, satisfaction). |

---

## Where it shows up

- **Slide deck:** Slide “The design process” now labels all four (Discover, Define, Develop, Deliver). Later, “Across the design process — discover, define, develop, deliver — the agent handles execution; you own direction and quality.”
- **Amendments:** Discovery → Ideation → Concept development → Prototyping → Development (handoff, cycles) → Delivery (partnership, pilots, training).
- **Insurance:** Discovery (usability testing, goals, synthesis) → Concept (integrated quoting, one-click add) → Development → Delivery (in-house, API, training).
- **About / Home:** Tools (Figma, Miro, research, prototyping, AI tools) and capabilities (Discovery & Framing, Prototyping & Iteration, etc.) align to these phases.

## Then vs Now (slide: by phase, then vs now)

The Then vs Now slide is structured by **discover, define, develop, deliver**. Each phase has a Then (spec-led handoff) and a Now (how you'd work with actual tech), with productivity and UI called out.

- **Discover** — Then: Workshops, manual synthesis, heavy alignment across time zones. Now: AI can synthesise and map flows from findings.
- **Define** — Then: Flowcharts and annotated prototypes for handoff; intent in docs. Now: AI generates flows and structure; you set direction, review and refine.
- **Develop** — Then: Handoff to build, 3‑month cycles, 12hr feedback, translation gaps. Now: Actual tech to generate real prototypes; agent keeps context; UI e.g. 9 screens → 3.
- **Deliver** — Then: Build and deploy; UAT, pilots, training; long cycles for fixes. Now: Faster iteration, fewer gaps, productivity gains carry through.

So the *process* (discover, define, develop, deliver) stays; *how* you do each phase (especially define and develop) shifts toward AI-generated flows and prototypes with you in review mode, and productivity/UI improvements are explicit.
